# 事例作成機能仕様書

## 概要
BRANU営業支援システムの事例作成機能。基本情報入力からAIヒヤリング、確認・編集まで3段階のワークフローで商談事例を作成する。

## 基本情報入力機能

### 1. 企業名
- **入力形式**: テキスト入力
- **必須項目**: Yes
- **文字数制限**: 1-100文字
- **バリデーション**: 空文字、特殊文字チェック
- **重複チェック**: 会社名+都道府県での重複防止
- **データ形式**: String

### 2. 業種選択
- **対象**: 建設業許可業種29業種
- **選択方式**: 複数選択可能（チェックボックス）
- **必須項目**: 最低1つ選択
- **メイン業種**: ラジオボタンで1つ指定（必須）
- **制約**: メイン業種は選択済み業種の中から選択
- **業種一覧**:
  - **一式工事業（2業種）**: 土木一式工事業、建築一式工事業
  - **専門工事業（27業種）**: 大工工事業、左官工事業、とび・土工工事業、石工事業、屋根工事業、電気工事業、管工事業、タイル・れんが・ブロック工事業、鋼構造物工事業、鉄筋工事業、舗装工事業、しゅんせつ工事業、板金工事業、ガラス工事業、塗装工事業、防水工事業、内装仕上工事業、機械器具設置工事業、熱絶縁工事業、電気通信工事業、造園工事業、さく井工事業、建具工事業、水道施設工事業、消防施設工事業、清掃施設工事業、解体工事業

### 3. 地域選択
- **都道府県**: 47都道府県からの必須選択
- **市区町村**: テキスト入力（任意）
- **階層構造**: 都道府県 → 市区町村
- **データ保存**: 新規市区町村は検索用DBに自動追加
- **バリデーション**: 都道府県は必須、市区町村は任意

### 4. 企業規模
- **選択肢**: 
  - 小規模（従業員数〜50名）
  - 中規模（従業員数50-300名）
  - 大規模（従業員数300名〜）
- **選択方式**: ラジオボタン（単一選択）
- **必須項目**: Yes
- **データ形式**: Enum

### 5. データバリデーション

#### 必須項目チェック
- **企業名**: 空文字禁止
- **業種**: 最低1つ選択
- **メイン業種**: 選択済み業種から1つ選択
- **都道府県**: 必須選択
- **企業規模**: 必須選択

#### 形式チェック
- **企業名**: 特殊文字・記号の制限
- **市区町村**: 全角文字推奨、英数字混在チェック
- **文字数**: 各項目の最大文字数制限

#### 論理チェック
- **メイン業種**: 選択済み業種リストに含まれること
- **業種重複**: 同一業種の重複選択防止
- **地域整合性**: 都道府県と市区町村の地理的整合性

## AIヒヤリング機能

### 1. 処理フロー（事例セット生成まで）

#### ヒアリング開始
ユーザーが基本情報入力後、「AIヒアリング開始」をクリック

#### 企業重複チェック・登録処理
**Next.js担当**: 企業情報の重複チェック・登録処理
```http
POST /api/companies/find-or-create
```

**リクエストボディ**:
```json
{
  "companyInfo": {
    "name": "株式会社例",
    "industries": ["建設業", "製造業"],
    "mainIndustry": "建設業",
    "prefecture": "東京都",
    "city": "新宿区",
    "companySize": "medium"
  }
}
```

**レスポンス**:
```json
{
  "data": {
    "companyId": "comp-12345",
    "isExisting": false,
    "message": "新規企業として登録されました"
  }
}
```

**Next.js処理内容**:
- 会社名+都道府県で既存企業をRDSから検索
- 存在する場合：既存企業IDを返却（isExisting: true）
- 存在しない場合：新規企業としてRDSに登録（isExisting: false）

#### 初期化処理
**Next.js → FastAPI**: 基本情報送信
```http
POST /api/ai-hearing/start(例)
```

**リクエストボディ**:
```json
{
  "basicInfo": {
    "companyId": "comp-12345",
    "companyName": "株式会社例",
    "industries": ["建設業", "製造業"],
    "mainIndustry": "建設業",
    "region": "関東",
    "prefecture": "東京都",
    "city": "新宿区",
    "companySize": "medium"

```

#### FastAPI処理
- AI初回メッセージ生成
- セッションID生成
- Redisにセッション保存（AIヒヤリング用一時データ）

**Redis保存データ**:
```json

    {
      "role": "assistant",
      "content": "初回メッセージ"
```

- Redis取得
- AI処理（Gemini API）
- 会話履歴更新
- Redis更新

### 3. 期限通知機能
- **保存期間**: Redis上で30日間保存
- **期限基準**: `deals.updated_at`から30日（最後の活動から30日間）
- **再開時**: `updated_at`が自動更新され、期限が30日延長される
- **開始時通知**: 「会話履歴は30日間保存され、その間再開可能です」
- **期限警告**: 残り7日以下で警告メッセージ表示
- **期限切れ**: 30日経過後は自動削除

### 4. 保存オプション処理

#### 一時保存選択

**Next.js担当: 一時保存処理**
- 保持中のデータ（基本情報・事例セット・会話履歴）でDB保存
- `/api/cases`でPOST送信（事例データ作成、status: 'in_progress'）
- `/api/conversation-history`でPOST送信（会話履歴保存）
- `/api/ai-hearing/session/{sessionId}`でDELETE送信（Redisセッション削除）
- 保存完了後、事例履歴画面へ遷移

**FastAPI担当: セッション削除**
- 指定されたRedisセッションを削除

#### 保存選択

**Next.js担当: 確認・編集・保存処理**
- 保持中のデータ（基本情報・事例セット・会話履歴）を確認・編集画面で表示
- ユーザーによる内容編集・deal結果選択（won/lost）
- 編集後、全データをDBに保存
- `/api/cases`でPOST送信（事例データ作成、status: 'won' or 'lost'）
- `/api/conversation-history`でPOST送信（会話履歴保存）
- `/api/ai-hearing/session/{sessionId}`でDELETE送信（Redisセッション削除）
- 保存完了後、事例検索画面へ遷移

### 5. AIヒヤリング再開処理

#### Next.js担当: データ取得・送信
1. **データ取得**: RDSから基本情報・事例セット・会話履歴を取得
2. **期限更新**: `deals.updated_at`をRDSで更新し、30日期限をリセット
3. **再開リクエスト**: `POST /api/ai-hearing/resume`で取得データを送信
4. **新セッションID取得**: FastAPIから新しいセッションIDを受け取り
5. **会話画面遷移**: 新セッションIDで会話継続画面を表示

#### FastAPI担当: セッション復元処理
- **新セッションID生成**: 元セッションは一時保存時に削除済み
- **新Redisセッション**: 受信したデータで新しいRedisセッションを作成
- **継続性**: 過去の会話履歴と事例データが引き継がれた状態で再開
